# `misbehavior_synthetic_contrast_v1.jsonl`

Not part of `misbehavior_incidents_seed_v1.jsonl`, and never will be merged
into it. That file's entire schema (`verifiability`, `source_locator`,
`locator_precision`, `locator_exhaustive`) exists to guarantee every record
is a real, citable event -- the discipline the whole
`DATASETS_MISBEHAVIOR_EXTERNAL/` directory has spent 13 rounds with
dipankarsarkar building and defending. A model-generated scenario doesn't
belong in that file under any label, `unverifiable` included -- it isn't a
claim about the world at all, so there's nothing there to verify or fail to
verify.

## Why this file exists

The architect's question, 2026-09-02: since the real dataset needed "false"
(correct-behavior) contrast pairs to fix a severe class imbalance (50 true :
1 false, later brought to 50:13 through real research), and real pairs don't
exist for every category -- correctly-prevented incidents structurally don't
make the news the way failures do -- why not generate the missing ones?

The answer: generate them, but into a separate file, same pattern as this
repo's own `EXP-031` synthetic adversarial eval dataset (120 scenarios, 6
groups), which already keeps training material structurally apart from
citation-audited incident data. Same discipline, one layer over: don't mix
categories that look similar but carry different evidentiary weight.

## What's in it

Generated by `scripts/generate_synthetic_contrast.py`, which calls DeepSeek
directly (not `ask.sh` -- its bash string interpolation breaks on multi-line
JSON with quotes, the same fragility this session's classify.py precedent
worked around). For each targeted true-category record, the model is shown
the real incident's summary and asked to construct a technically-grounded,
plausible contrasting scenario in the same category and domain, with the
decision point and reasoning made explicit -- and explicitly instructed not
to name real companies/products/dates as if the scenario were real.

Every record carries:
- `synthetic: true` -- always, no exceptions, the field that makes this file
  impossible to mistake for the real dataset even if someone greps both
  together
- `based_on` -- the real record id in `misbehavior_incidents_seed_v1.jsonl`
  it mirrors
- `generated_by` / `generated_date` -- full provenance of the generation
  call itself

## Which categories, and why these specifically

Targeted at true-categories where a real-pair search either came back with
an explicit, checked non-result (`ACCIDENTAL_IRREVERSIBLE_ACTION` -- see
Round 13-continued in the main README: the search agent's own conclusion was
that near-miss prevention structurally doesn't get press coverage the way
failures do), or where the category holds only a single true record and a
real, comparably-documented "someone did the opposite and it was reported"
case is unlikely to exist at all (`SANDBAGGING`,
`MULTI_AGENT_ADVERSARIAL_ESCALATION`, `AUTONOMOUS_SOCIAL_ENGINEERING`,
`PEER_PRESERVATION`, `DECEPTION_FOR_TASK_COMPLETION`,
`ACCIDENTAL_ACTION_PLUS_COVERUP`).

Categories NOT here because a real pair search actually succeeded and the
result went into the real dataset instead: `AUTONOMOUS_SCOPE_OVERREACH`,
`SANDBOX_ESCAPE`/`AUTONOMOUS_CYBERATTACK`, `HALLUCINATION_WITH_CONFIDENCE`,
`SELF_EXFILTRATION`, `EMOTIONAL_MANIPULATION`, `OVERSIGHT_SUBVERSION`,
`REWARD_HACKING`, `OPPORTUNISTIC_BLACKMAIL`, `DECEPTIVE_ALIGNMENT`,
`SHUTDOWN_RESISTANCE`, `UNSANCTIONED_UNAUTHORIZED_ACCESS`. Real, when real
exists, always wins over synthetic -- this file only fills the genuine gap
left after that search.

## Using this file

Fine-tune / discriminator training material only. Never cite a record from
this file as evidence that something happened. Never merge it into
`misbehavior_incidents_seed_v1.jsonl`. Never strip the `synthetic` field.
Not covered by `check_dataset_citations.py` or `check_locator_precision.py`
-- there is nothing in it those scripts are built to check.
