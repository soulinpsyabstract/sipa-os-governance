# Causal-chain / probability / risk pipeline datasets

Generated 2026-09-21 via OpenRouter (`nousresearch/hermes-4-405b`), for the three stages of the
consequence-prediction pipeline documented in `project_consequence_prediction_architecture.md`
(memory) and the "Consequence Pipeline" artifact
(https://claude.ai/code/artifact/e8f4400a-ebbf-406b-9aef-aa5fa6632bec). Ordering fixed by the
architect and independently confirmed by the self-hosted stage6_governance_safety_b model
(sipa-llm.sipa-os.online): **causal chain → probability → M2M verification** — not the other way
around.

## 1. Causal chain (structural, no numbers)

| File | N | Risk group |
|---|---|---|
| `causal_chain_vulnerability.jsonl` | 200 | a security vulnerability introduced/exposed/exploited |
| `causal_chain_deletion.jsonl` | 200 | loss of data/infra via deletion/overwrite/destructive op |
| `causal_chain_sensitive_publication.jsonl` | 200 | sensitive/private info becoming publicly exposed |

Each record: `action_x` (the initiating action) → `chain` (an ordered list of 3-4 steps, X→Y→Z) →
`terminal_outcome` (the concrete harm). No probabilities anywhere in this layer — purely
"what leads to what", matching `CAUSAL_CHAIN_WALKER.py`'s existing deterministic-graph-walk design.

## 2. Probability (annotates the chains above, does not invent new ones)

| File | N |
|---|---|
| `probability_vulnerability.jsonl` | 200 |
| `probability_deletion.jsonl` | 200 |
| `probability_sensitive_publication.jsonl` | 200 |

Each record references a `chain_ref` (id from dataset 1) and adds `probability_estimate` (0.0-1.0)
+ `probability_reasoning` — the likelihood that this specific already-identified chain actually
completes to its harmful terminal outcome. Explicitly instructed to vary (not default to
"everything is high risk"): observed range 0.2-0.95 across all three groups.

## 3. Risk / sensitive-info classification (what counts as harmful — feeds Impact, not P)

| File | N | Status |
|---|---|---|
| `risk_harvested_from_governance_canon.jsonl` | 11 | **already decided** — pulled from real SIPA OS incidents (VIO-001, 006, 007, 008, 009, 010, 011, 012) and CLAUDE-BRIEF Rule #13, `decided_by: "architect"` |
| `risk_candidates_vulnerability.jsonl` | 200 | **pending architect review** — `decided_by: null` |
| `risk_candidates_deletion.jsonl` | 200 | **pending architect review** — `decided_by: null` |
| `risk_candidates_sensitive_publication.jsonl` | 200 | **pending architect review** — `decided_by: null` |

Each record: an `item` (a concrete file type / action / config / data type) + a proposed
`is_risky` true/false + `reasoning`. This is the classification ground truth that feeds the
`Impact(harmful Y)` side of `Risk(X|C) = P(harmful Y|X,C) × Impact(harmful Y)` — a binary a model
cannot invent on its own, per the architect's own point: a binary classifier only knows true/false
if the truth comes from somewhere external to it. The 11 harvested records are real, already-decided
incidents; the 588 candidates were generated with a balanced true/false mix (not "everything is
risky") and are explicitly marked unverified until the architect reviews them in small batches.

**Total: 1811 records across 10 files.**

Verified before push: no real secrets, IPs, domains, or names leaked into any file (checked against
CLAUDE-BRIEF Rule #13's grep pattern plus ZeroTier IP / sipa-os domain / architect-name patterns —
0 matches; the only `sk-` string hits are a redacted reference to the already-revoked VIO-011 key
and two clearly-fake `sk-example-...` placeholders generated by the model itself).
